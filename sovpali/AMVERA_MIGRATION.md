## Развёртывание

1. Создать отдельную пустую PostgreSQL в Moscow-1. Не использовать `DATABASE_URL`
   Render и не импортировать пользователей, заказы, очереди рассылок и платежи.
2. Создать приложение с достаточной памятью (не ниже 512 МБ, как текущий Render).
3. Подключить GitHub-репозиторий, ветку подготовки; корнем сборки является корень
   репозитория. `amvera.yaml` выбирает `sovpali/Dockerfile.amvera` и порт 10000.
4. Задать переменные и секреты до первой сборки. Для просмотра обязательны
   `STANDBY_USERNAME` и `STANDBY_PASSWORD` (не менее 24 символов).
5. Новый `DATABASE_URL` должен указывать только на новую БД. Хранить пароль в
   секретах Amvera. Не открывать БД наружу для работы приложения.
6. Оставить `SOVPALI_RUNTIME_MODE=standby`. Образ по умолчанию запускает именно
   этот режим. Не менять команду запуска на `setup_runner.py` или `app.py`.
7. Проверить `/health`: `database=true`, `mode=standby`, `bot=false`, `payments=false`.
   Проверить отсутствие пользователей и заказов после инициализации схемы.

## Защита от второго рабочего экземпляра

Режим standby импортирует полное приложение и создаёт схему, но не запускает
Telegram-поток, webhook registration, обновление меню/профиля бота, планировщики
знакомств, банковскую сверку и админские рассылки. В памяти используется заведомо
нерабочий Telegram-токен, сохранённый секрет Amvera не изменяется.

Ozon в standby принудительно отключён, транспорт банковского API также блокируется.
Входящие Telegram/Ozon уведомления и внутренние API возвращают 503. Просмотр сайта
требует отдельной Basic-авторизации, все изменяющие HTTP-запросы отключены. Поэтому
полноценная авторизация Mini App и пользовательские действия в standby недоступны;
это временная блокировка среды, исходные обработчики сохранены.

## Переменные

Сверить с фактическим Render Environment, включая подключённые группы и secret files.
Не выводить значения в чате или логах. Не переносить всё окружение вслепую.

| Группа | Действие |
| --- | --- |
| `DATABASE_URL` | Новая БД Amvera; не копировать старую строку подключения |
| `BOT_TOKEN`, `WEBHOOK_SECRET` | Сохранить секретами; standby не использует рабочего бота |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `FLASK_SECRET` | Сверить назначение и перенести в секреты |
| `OZON_PAY_ACCESS_KEY`, `OZON_PAY_SECRET_KEY`, `OZON_PAY_NOTIFICATION_SECRET_KEY` | Перенести секретами без перевыпуска и без платежей |
| `OZON_PAY_API_URL`, `OZON_PAY_MODE`, фискальные и продуктовые флаги | Зафиксировать исходные значения отдельно; standby отключает платежи в процессе |
| `PUBLIC_URL`, `WEBHOOK_BASE_URL` | Новый HTTPS-адрес Amvera; регистрация Telegram webhook в standby не выполняется |
| `SOVPALI_BOT_USERNAME` | Сверить с read-only Telegram `getMe` |
| `OPENAI_API_KEY`, `SOVPALI_AI_MODEL` | Перенести при наличии: используются помощником в переписке |
| `PROJECT_ADMIN_SECRET`, `TG_FUNNEL_BOT_TOKEN` | Не копировать автоматически: связаны с отдельным проектом «Поехали» |
| `B2_*`, `BACKUP_ENCRYPTION_KEY` | Проверить отдельный префикс/расписание, не перезаписывать резервные копии Render |
| `PORT`, `SOVPALI_RUNTIME_MODE` | `10000`, `standby` |
| `STANDBY_USERNAME`, `STANDBY_PASSWORD` | Отдельные данные доступа к закрытому просмотру |

Точные настройки Telegram (`getWebhookInfo`, `getChatMenuButton`, main Mini App
в BotFather) и кабинета Ozon ещё нужно сверить после получения доступа. Код передаёт
notificationUrl при создании платежа; уже созданные платежи остаются связанными со
старым адресом. Проверка HTTP страниц сама по себе не подтверждает эти настройки.
`OZON_PAY_SETUP.md` исторический и не описывает актуальную реализованную интеграцию.

## Проверено локально

- Выполнена последовательность исторических преобразований из Dockerfile.
- Все 33 тестовых скрипта существующей сборки прошли с `TZ=UTC`, как в контейнере.
  Один тест приглашений зависит от UTC и сначала не прошёл в часовом поясе Mac.
- Четыре новых теста проверяют запрет внешнего банковского запроса, отсутствие
  фоновых потоков, пустую локальную SQLite-схему и блокировку изменяющих запросов.
- Mini App собрана через Vite. Настоящие платежи и сообщения Telegram не выполнялись.
- Полная Docker-сборка и интеграция с новой PostgreSQL ещё требуют проверки
  в Amvera; локально Docker отсутствует.
- Render `/health`, `/s/app`, `/billing/pay` отвечают HTTP 200; `/health` сообщает `bot=true`.

## Переключение — только после отдельного разрешения

До разрешения не менять Telegram webhook, BotFather/main Mini App, меню бота,
банк или режим Amvera на active. При переключении сначала остановить все рабочие
потоки бота на Render, затем активировать Amvera. Никогда не держать два активных
экземпляра. План сохранения старых платёжных уведомлений согласовать отдельно,
поскольку пустая новая БД не содержит прежних заказов. Render не удалять.
