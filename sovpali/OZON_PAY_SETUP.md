# Совпали — подключение Ozon Pay через СБП и карту

## Текущее состояние

- /billing/demo — оформление с выбором карты/СБП; оплата активна **только для самостоятельного теста 100 ₽**, если в Render задана официальная ссылка Ozon Pay.
- /billing/return/success и /billing/return/fail — страницы возврата из Ozon Pay. Возврат на URL никогда сам по себе не подтверждает списание.
- Реальное создание заказов, подписание запросов банка, проверка событий и выдача цифрового доступа по оплаченному заказу пока **не реализованы**.
- Пока тестируем взаимное согласие в Telegram, эквайринг не включаем.

## Где будут храниться ключи и как их заменить

В https://dashboard.render.com открой Web Service «Совпали» → **Environment** → **Add Environment Variable**. Там вводятся серверные секреты. Не вставляй их в GitHub или Telegram.

Новые ключи можно заменить в той же панели; Render обновит переменные окружения сервиса. Отдельной платы за стандартное хранение переменных нет в рамках работы сервиса.

## Защита ключей

Ozon рекомендует немедленно отключать токен, если его секретные ключи стали доступны сторонним лицам. Источник: https://docs.ozon.ru/common/yuridicheskim-litsam/ozon-pay/tilda/

Деактивируйте старый токен в Ozon Банке → Эквайринг → Магазины → Интеграция и выпустите новый, выбрав **Тестовый режим**.

В Render → сервис «Совпали» → Environment добавьте новые ключи **напрямую**, не помещая их в GitHub, чаты, логи и не присылая скриншоты значений.

Названия переменных (для будущей интеграции):
- OZON_PAY_MODE = disabled
- OZON_PAY_ACCESS_KEY = [новый ID токена]
- OZON_PAY_SECRET_KEY = [новый секретный ключ]
- OZON_PAY_NOTIFICATION_SECRET_KEY = [новый секрет для нотификаций]

Сейчас эти имена ещё не используются кодом, и их добавление не создаст оплату. OZON_PAY_MODE оставлять disabled до завершения интеграции.

## Быстрая самостоятельная проверка списания 100 ₽ по ссылке Ozon Pay

Возможность **не связана с ключами API**: если Ozon Pay уже одобрил приём платежей, в кабинете эквайринга можно вручную сформировать банковскую платёжную ссылку.

1. В кабинете Ozon Банка откройте раздел эквайринга и найдите создание платёжной ссылки. Установите **ровно 100 ₽**, название реальной услуги, правильный магазин и фискальные параметры. Проверьте официальный домен ссылки.
2. В Render → сервис «Совпали» → **Environment** создайте переменную **OZON_PAY_TEST_100_URL** и вставьте полную HTTPS-ссылку, сформированную Ozon.
3. На https://one2-1o22.onrender.com/billing/demo выберите позицию **«Проверить эквайринг» — 100 ₽**. Кнопка активируется **только** при наличии ссылки, которая ведёт на домен Ozon. Другие позиции (900/1200 ₽) остаются без активной оплаты.
4. Нажмите кнопку и на странице Ozon Pay проверьте магазин, назначение и сумму **100 ₽** до подтверждения. Выберите карту или СБП, если этот способ доступен на банковской странице.
5. После списания **сверьте транзакцию в банковском кабинете**, а не по факту перехода на нашу страницу успеха. Этот шлюз **не создаёт заказ в нашей базе и не открывает услугу автоматически**. Если оплата не прошла, проверьте статус в банке, прежде чем повторять.

Это настоящий банковский платёж, а не песочница, **только после подключения оператором такой ссылки**. Не включайте этот сценарий для массовых клиентов: нет привязки заказов, подтверждения по API, электронной выдачи и автоматизированного возврата. Если ссылка одноразовая, после теста удалите переменную или создайте новую.

Не помещайте в эту переменную API-ключи и ранее раскрытые секреты. Для полноценной Ozon Acquiring API-интеграции нужны **новые, не раскрытые** ключи и проверка банковских уведомлений.

**Важно:** цифровые услуги, продаваемые пользователям бота или Mini App внутри Telegram, должны оплачиваться через Telegram Stars. Этот шлюз предназначен исключительно для самостоятельной проверки банковского эквайринга отдельно от бота.

## Что требуется сделать до включения денег

1. Согласовать с Ozon Pay реальные услуги «Совпали» и данные магазина (старый магазин называется Digital Skill).
2. На сайте разместить реквизиты ИП, оферту, условия возврата, контакты, политику данных, цены и описание выдачи услуги.
3. По актуальной документации https://docs.ozon.ru/api/acquiring реализовать создание заказа на сервере и подпись запроса, строго по банковскому протоколу.
4. Хранить заказ, сумму в копейках, валюту и вид услуги на сервере, не доверяя сумме из браузера.
5. Принимать и верифицировать банковские уведомления только по официальной спецификации; дополнительно проверять реальный статус заказа в API.
6. Открывать доступ только после подтверждения подлинного успешного платежа с правильными ID и суммой; делать выдачу идемпотентной.
7. Проверить тестовые и отказные сценарии, отмены, возвраты, повторы, ошибки сети и фискальные чеки.
8. Оплата картой должна открываться только на стороне Ozon Pay, никакого ввода номера карты/CVV у нас. Для СБП — банковский перевод или QR по возможностям провайдера.

## Telegram

Цифровые услуги, продаваемые в Telegram-ботах или Mini Apps внутри Telegram, по правилам Telegram должны оплачиваться Stars. Вынос оплаты на внешнюю страницу, если покупка инициирована из бота, этого требования не обходит. Ozon Pay возможен для самостоятельного веб-сервиса с отдельным каналом продаж.

Источник: https://core.telegram.org/bots/payments-stars
